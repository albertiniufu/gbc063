O algoritmo, linha por linha

O pseudocódigo à esquerda executa de verdade: uma rede neural minúscula aprende a atravessar um labirinto 5×5 com paredes (intransponíveis) e poços ☠ — estados terminais com recompensa −1. A cada linha, os símbolos abstratos (φ, at, rt, yj, θ⁻) aparecem preenchidos com os valores daquele instante, e os mapas de calor mostram os pesos sendo treinados: assista o ciano se espalhar a partir da saída e o vermelho brotar ao redor dos poços.

Por que essa linha existe

O problema tem dois tipos de terminal: a saída (+1) e os poços (−1). A linha do yj trata os dois do mesmo jeito — "se termina, y = r" — e é assim que o medo do poço se propaga para trás pelo mapa.

O que está acontecendo

O jogo é o Catch: uma bola cai do topo em coluna aleatória; a raquete (2 pixels) escolhe ← · → a cada passo; pegar vale +1, deixar cair vale −1. É a miniatura clássica do Breakout — um jogo de verdade, com física própria rodando em tempo real, e não um cenário estático.

A rede não recebe coordenadas: recebe os 36 pixels crus da tela 6×6 (bola e raquete acesos), exatamente como o DQN original recebia a tela do emulador. φ aqui é a própria imagem binarizada. Arquitetura: 36 → 32 tanh → 3 valores de ação, com replay, rede alvo e ε-guloso — o mesmo algoritmo da outra aba.

A grade ao lado é o Q de todas as situações simultaneamente: cada linha é uma altura da bola (de recém-lançada, no topo, a prestes a cair), cada coluna é a posição relativa bola−raquete. Cor = V(s) = max Q; seta = ação preferida. Aperte o botão e assista à onda: o ciano nasce na linha de baixo, nas colunas 0 e +1 (tracejadas: onde a bola cai na raquete), e sobe linha a linha, com γ = 0,9 descontando a cada altura — enquanto as setas passam a apontar para dentro da zona de captura.

Replay priorizado (PER): em vez de sortear todas as memórias com a mesma chance, cada transição carrega uma prioridade proporcional ao erro que a rede cometeu nela — quem foi mal previsto volta com mais frequência, como revisar mais as questões que você errou. Para o sorteio enviesado não distorcer o aprendizado, cada amostra recebe um peso de importância que encolhe seu gradiente na medida exata do favorecimento (o expoente β cresce de 0,4 a 1 ao longo do treino).

Dueling DQN: muda a cabeça da rede, não o algoritmo. Em vez de estimar Q(s,a) direto, o tronco compartilhado alimenta dois ramos — V(s), "quanto vale estar aqui", e A(s,a), "quanto cada ação muda isso" — combinados como Q = V + A − média(A). A vantagem aparece nos estados onde a escolha quase não importa (bola no topo: qualquer ação serve): o ramo V aprende o valor da situação de uma vez, sem precisar reaprender por ação, e o A gasta capacidade só onde a decisão pesa — a linha de baixo da grade. As três chaves combinam: Double + PER + Dueling é o embrião do Rainbow.

Célula 2 · Ambiente do labirinto 5×5 (paredes e poços) instantâneo 
# Mesmo mapa da aba "Labirinto": saída (4,4)=+1, poços=−1, passo=−0,02,
# bater na parede = ficar parado, limite T=40, nascimento aleatório em casa livre.
S = 5
GOAL  = (4, 4)
WALLS = {(1,1), (3,1), (1,2), (2,3)}
PITS  = {(3,0), (3,3), (0,4)}
ACOES = [(0,-1), (1,0), (0,1), (-1,0)]   # ↑ → ↓ ←
ANOMES = "↑→↓←"
T_MAX = 40

def idx(s): return s[1]*S + s[0]
def livre(c): return c not in WALLS and c not in PITS and c != GOAL

def passo(s, a):
    nx, ny = s[0]+ACOES[a][0], s[1]+ACOES[a][1]
    ns = (nx, ny) if 0 <= nx < S and 0 <= ny < S and (nx, ny) not in WALLS else s
    if ns == GOAL:   return ns,  1.0, True
    if ns in PITS:   return ns, -1.0, True
    return ns, -0.02, False

def nascer():
    while True:
        c = (random.randrange(S), random.randrange(S))
        if livre(c): return c

def phi(s):
    """Pré-processamento: one-hot de 25 posições — a compressão da história."""
    v = torch.zeros(25); v[idx(s)] = 1.0
    return v
Célula 3 · DQN do labirinto: treinar 300 episódios ~20 s na CPU 
# Hiperparâmetros idênticos aos do simulador:
# rede 25→24 tanh→4 · γ=0.95 · lr=0.035 · lote=8 · memória=56 · C=25 · ε 1.0→0.05
GAMMA, LR, BATCH, CAP, C = 0.95, 0.035, 8, 56, 25

def nova_rede():
    return nn.Sequential(nn.Linear(25, 24), nn.Tanh(), nn.Linear(24, 4)).to(device)

Q    = nova_rede()
Qhat = nova_rede(); Qhat.load_state_dict(Q.state_dict())   # θ⁻ = θ
opt  = torch.optim.SGD(Q.parameters(), lr=LR)
D    = collections.deque(maxlen=CAP)                       # memória de replay
eps, desde_copia, retornos = 1.0, 0, []

def treina_lote():
    global desde_copia
    if len(D) < BATCH: return
    lote = random.sample(list(D), BATCH)
    x   = torch.stack([phi(b[0]) for b in lote]).to(device)
    a   = torch.tensor([b[1] for b in lote], device=device)
    r   = torch.tensor([b[2] for b in lote], device=device)
    x2  = torch.stack([phi(b[3]) for b in lote]).to(device)
    fim = torch.tensor([b[4] for b in lote], device=device)
    with torch.no_grad():                                  # alvo fixo: y vem de Q̂
        y = r + GAMMA * Qhat(x2).max(1).values * (~fim).float()
    q = Q(x).gather(1, a.unsqueeze(1)).squeeze(1)
    loss = ((y - q)**2).mean()
    opt.zero_grad(); loss.backward(); opt.step()
    desde_copia += 1
    if desde_copia >= C:                                   # sincronização θ⁻ ← θ
        Qhat.load_state_dict(Q.state_dict()); desde_copia = 0

for ep in range(300):
    s, ret, fim = nascer(), 0.0, False
    for t in range(T_MAX):
        eps = max(0.05, eps*0.992)
        with torch.no_grad():
            a = random.randrange(4) if random.random() < eps \
                else Q(phi(s).to(device)).argmax().item()
        ns, r, fim = passo(s, a)
        D.append((s, a, r, ns, fim)); ret += r; s = ns
        treina_lote()
        if fim: break
    retornos.append(ret)

# Tela 6×6; a bola cai em coluna aleatória; raquete de 2 pixels na base.
# A rede recebe os 36 pixels crus — nunca coordenadas.
W, H, PW = 6, 6, 2

def tela(bx, by, px):
    v = torch.zeros(H, W)
    v[by, bx] = 1.0
    v[H-1, px:px+PW] = 1.0
    return v.flatten()
Célula 6 · Redes, PER e as estratégias de alvo instantâneo 
class Padrao(nn.Module):
    """36 → 32 tanh → 3 (Q direto por ação)."""
    def __init__(self):
        super().__init__()
        self.f = nn.Sequential(nn.Linear(36, 32), nn.Tanh(), nn.Linear(32, 3))
    def forward(self, x): return self.f(x)

class Dueling(nn.Module):
    """Tronco compartilhado → V(s) e A(s,a); Q = V + A − média(A)."""
    def __init__(self):
        super().__init__()
        self.tronco = nn.Sequential(nn.Linear(36, 32), nn.Tanh())
        self.V = nn.Linear(32, 1)
        self.A = nn.Linear(32, 3)
    def forward(self, x):
        h = self.tronco(x)
        A = self.A(h)
        return self.V(h) + A - A.mean(dim=-1, keepdim=True)

class ReplayPER:
    """Prioritized Experience Replay (variante proporcional).
    p_i = (|erro TD| + 0.01)^0.6 · sorteio ∝ p_i · pesos de importância com β 0.4→1."""
    def __init__(self, cap, alpha=0.6):
        self.cap, self.alpha = cap, alpha
        self.dados, self.pri, self.max_p = [], [], 1.0
    def __len__(self): return len(self.dados)
    def push(self, tr):
        self.dados.append(tr); self.pri.append(self.max_p)  # novato = prioridade máxima
        if len(self.dados) > self.cap:
            self.dados.pop(0); self.pri.pop(0)
    def amostra(self, n, beta):
        p = np.asarray(self.pri); P = p / p.sum()
        ids = np.random.choice(len(self.dados), n, p=P)
        w = (len(self.dados) * P[ids]) ** (-beta)
        w = w / w.max()                                     # maior peso = 1
        return ids, [self.dados[i] for i in ids], torch.tensor(w, dtype=torch.float32)
    def atualiza(self, ids, erros):
        for i, e in zip(ids, erros):
            self.pri[i] = (abs(float(e)) + 0.01) ** self.alpha
            self.max_p = max(self.max_p, self.pri[i])

def treinar_catch(estrategia="c150", replay="uni", arquitetura="std",
                  episodios=4000, C=150, gamma=0.9, lr=0.05, batch=16, cap=600):
    """estrategia: 'c1' (sem alvo fixo) | 'c150' (alvo fixo) | 'double'
       replay:     'uni' | 'per'
       arquitetura:'std' | 'duel'
       Hiperparâmetros idênticos aos da aba Atari do simulador."""
    Rede = Dueling if arquitetura == "duel" else Padrao
    Q, Qhat = Rede(), Rede(); Qhat.load_state_dict(Q.state_dict())
    opt = torch.optim.SGD(Q.parameters(), lr=lr)
    per = ReplayPER(cap) if replay == "per" else None
    D = collections.deque(maxlen=cap)
    eps, beta, desde = 1.0, 0.4, 0
    ultimos, curva = collections.deque(maxlen=100), []
    px = (W - PW) // 2                       # a raquete persiste entre episódios

    for ep in range(episodios):
        bx, by, fim = random.randrange(W), 0, False
        while not fim:
            x = tela(bx, by, px)
            eps = max(0.05, eps*0.9985); beta = min(1.0, beta + 2e-5)
            with torch.no_grad():
                a = random.randrange(3) if random.random() < eps else Q(x).argmax().item()
            px = min(max(px + a - 1, 0), W - PW)
            by += 1
            fim = (by == H - 1)
            r = (1.0 if px <= bx < px + PW else -1.0) if fim else 0.0
            tr = (x, a, r, tela(bx, by, px), fim)
            per.push(tr) if per else D.append(tr)
            if (len(per) if per else len(D)) >= 64:
                if per:
                    ids, lote, w = per.amostra(batch, beta)
                else:
                    lote, w = random.sample(list(D), batch), torch.ones(batch)
                xs   = torch.stack([b[0] for b in lote])
                as_  = torch.tensor([b[1] for b in lote])
                rs   = torch.tensor([b[2] for b in lote])
                x2s  = torch.stack([b[3] for b in lote])
                fims = torch.tensor([b[4] for b in lote])
                with torch.no_grad():
                    if estrategia == "c1":         # a própria rede escolhe E avalia
                        prox = Q(x2s).max(1).values
                    elif estrategia == "double":   # Q escolhe, Q̂ avalia
                        a2 = Q(x2s).argmax(1, keepdim=True)
                        prox = Qhat(x2s).gather(1, a2).squeeze(1)
                    else:                          # DQN clássico: max único em Q̂
                        prox = Qhat(x2s).max(1).values
                    y = rs + gamma * prox * (~fims).float()
                q = Q(xs).gather(1, as_.unsqueeze(1)).squeeze(1)
                erros = y - q
                loss = (w * erros**2).mean()       # w = pesos de importância (1 se uniforme)
                opt.zero_grad(); loss.backward(); opt.step()
                if per: per.atualiza(ids, erros.detach())
                if estrategia != "c1":
                    desde += 1
                    if desde >= C:
                        Qhat.load_state_dict(Q.state_dict()); desde = 0
        ultimos.append(1 if r > 0 else 0)
        curva.append(sum(ultimos) / len(ultimos))
    return Q, curva

A base (antes do “deep”)
Q-learning
Watkins & Dayan · Machine Learning 8, 279–292 · 1992
A prova de convergência do Q-learning tabular: os valores de ação convergem para o ótimo desde que todo par (estado, ação) seja visitado infinitas vezes. É a tabela que a rede neural veio substituir.
No simulador: é o algoritmo por trás de tudo — a atualização y = r + γ·max Q é a regra de Watkins; a rede só troca a tabela por 700 pesos.
também: PDF gratuito na página do Dayan
Self-improving reactive agents based on reinforcement learning, planning and teaching
Long-Ji Lin · Machine Learning 8, 293–321 · 1992
A origem do experience replay, duas décadas antes do DQN: guardar experiências e reaprender delas várias vezes para acelerar agentes conexionistas lentos.
No simulador: a memória D das abas Labirinto e Atari — os quadradinhos que enchem e são ressorteados.
The Arcade Learning Environment: an evaluation platform for general agents
Bellemare, Naddaf, Veness & Bowling · JAIR 47 · 2013 · arXiv:1207.4708
A plataforma que empacota o emulador Stella de Atari 2600 como benchmark de pesquisa — o motivo de o pseudocódigo falar em “emulador” e chamar a observação de “imagem”.
No simulador: o painel “Emulador” da aba Labirinto e o Catch de pixels fazem o papel do ALE: caixa-preta que devolve só r e x.
Reinforcement Learning: An Introduction (2ª ed.)
Sutton & Barto · MIT Press · 2018 · livro completo gratuito
O livro-texto da área. Capítulo 6 cobre TD e Q-learning; o vocabulário formal de estado, retorno, γ e ε-guloso vem daqui.
No simulador: todo o dicionário de símbolos (γ, ε, retorno, política gulosa) segue a notação deste livro.
O DQN — o pseudocódigo do simulador
Playing Atari with Deep Reinforcement Learning
Mnih, Kavukcuoglu, Silver et al. (DeepMind) · NIPS Deep Learning Workshop · 2013 · arXiv:1312.5602
O primeiro DQN: rede convolucional lendo pixels crus + experience replay. Ainda sem rede alvo — o y era calculado pela própria rede em treino.
No simulador: é exatamente a opção C = 1 · sem alvo fixo do seletor da aba Atari (e o seletor C = 1 da aba Labirinto).
Human-level control through deep reinforcement learning
Mnih et al. (DeepMind) · Nature 518, 529–533 · 2015 · doi:10.1038/nature14236
A versão da Nature que adiciona a rede alvo Q com sincronização a cada C passos e atinge nível humano em 49 jogos. O pseudocódigo da imagem que originou este simulador é o Algorithm 1 deste paper.
No simulador: é o algoritmo inteiro da aba Labirinto, linha por linha, e a opção C = 150 · alvo fixo da aba Atari.
As variantes dos seletores
Double Q-learning
Hado van Hasselt · NeurIPS 23, 2613–2621 · 2010
Identifica a raiz da superestimação: usar o max de estimativas ruidosas como estimativa do max verdadeiro tem viés positivo. Propõe dois estimadores independentes, um escolhendo e outro avaliando — ainda no cenário tabular.
No simulador: é a teoria por trás do toggle Double: por que “um max único adora superestimar”.
Deep Reinforcement Learning with Double Q-learning
van Hasselt, Guez & Silver (DeepMind) · AAAI · 2016 · arXiv:1509.06461
Leva a ideia de 2010 ao DQN sem rede extra: reutiliza a rede alvo como segundo estimador — Q escolhe a ação do próximo estado, Q dá a nota. Mostra que o DQN original superestimava sistematicamente nos jogos de Atari.
No simulador: a opção Double DQN nos dois seletores; ligar o toggle na aba Labirinto reescreve a linha do yj com esta fórmula.
Prioritized Experience Replay
Schaul, Quan, Antonoglou & Silver (DeepMind) · ICLR · 2016 · arXiv:1511.05952
Sortear memórias proporcionalmente ao erro TD (|δ|+ε)^α em vez de uniformemente, corrigindo o viés com pesos de importância (N·P)^−β, β recozido até 1. Transições novas entram com prioridade máxima.
No simulador: a opção Priorizado (PER) da aba Atari e a classe ReplayPER da célula 6 do notebook — α = 0,6 e β 0,4 → 1 são os valores deste paper.
Dueling Network Architectures for Deep Reinforcement Learning
Wang, Schaul, Hessel, van Hasselt, Lanctot & de Freitas · ICML · 2016 · arXiv:1511.06581
Separa a cabeça da rede em V(s) e A(s,a), combinadas como Q = V + A − média(A): o valor do estado é aprendido uma vez, sem repetir por ação, e a vantagem gasta capacidade só onde a escolha importa.
No simulador: a opção Dueling da aba Atari e a classe Dueling do notebook — a subtração da média é a eq. (9) do paper.
Rainbow: Combining Improvements in Deep Reinforcement Learning
Hessel et al. (DeepMind) · AAAI · 2018 · arXiv:1710.02298
Combina seis extensões do DQN (Double, PER, Dueling, n-step, distribucional C51, Noisy Nets) e mostra por ablação que elas são complementares.
No simulador: a combinação Double + PER + Dueling dos seletores é o “embrião do Rainbow” citado na nota da aba Atari — faltam as outras três peças.

Sobre o Catch
jogo didático · sem paper próprio
O Catch não tem um paper canônico: é uma miniatura de Breakout usada há anos em tutoriais e demonstrações como o menor ambiente honesto de “aprender dos pixels” — bola numa tela binária, três ações, recompensa ±1. A implementação da aba Atari segue essa tradição.
No simulador: o jogo inteiro da aba Atari.
